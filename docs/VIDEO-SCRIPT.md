# 演示视频分镜脚本（3–5 分钟）

> 配套文档：`docs/DEMO-SCRIPT.md`（现场演示的逐步口述稿）。这份是**录屏分镜**：每个镜头写清画面、操作、旁白与时长，可照着直接录。
> 目标是让面试官在 4 分钟内看到：知识问答、工具调用、执行轨迹、审批护栏、评测闭环。

## 录制前准备（10 分钟）

1. **分辨率与窗口**：1920×1080；浏览器缩放到 100%，隐藏书签栏，只留一个标签页。
2. **启动服务**：双击 `start-all.bat`（或 `docker compose up -d`），确认 8000/5173/5174 都通。
3. **预生成一条轨迹**（镜头 5 用）：

```powershell
$body = '{"question":"订单 SO20260901001 现在什么状态，物流到哪了","workflow_mode":"tools"}'
$resp = Invoke-RestMethod -Uri "http://127.0.0.1:8000/ask" -Method Post -Body $body -ContentType "application/json"
$resp.trace_id
```

把这个 `trace_id` 记下来，镜头 5 直接打开 `http://127.0.0.1:5173/?trace=<trace_id>`。

4. **清空干扰**：管理员控制台点「新会话」；终端字号调到 16+，只留评测那一行命令。
5. **录音环境**：用耳机麦克风；如果现场吵，先录屏、后期再配音（旁白稿见文末）。

推荐工具：Windows 自带 `Win + G`（简单）或 OBS（可多场景切换）；剪辑用剪映专业版（自动字幕很省事）。

## 旁白逐字稿（可直接照读）

**镜头 1**
> 这是一个企业智能客服系统。知识问题走 RAG 检索生成，业务问题走工具调用，答不出来或涉及敏感操作就转人工；每次执行都有轨迹，还有一套 150 条的可复现评测。

**镜头 2**
> 左边是知识库：产品手册、FAQ、售后与物流政策，导入后会被切分成片段并建立向量与关键词双索引。统计区能看到资料数、分片数、FAQ 数和工单数。

**镜头 3**
> 先问一个标准问题。这条命中了 FAQ，走的是规则匹配，不调用大模型——零 token 成本、也没有生成延迟，答案带来源引用，可以展开看原文。

**镜头 4**
> 再问一个需要实时数据的问题。订单状态不在知识库里，所以系统走结构化工具查询；这条答案是工具返回字段拼装的，不经过模型，手机号在工具层就脱敏了。

**镜头 5**
> 每次工具模式的任务都会生成 trace_id。这里能看到意图路由、工具调用、状态码、耗时和 token，链接可以直接发给同事复现同一次执行。

**镜头 6**
> 如果问题里同时提到订单和物流，系统会组合两个工具：先查订单状态，再补物流轨迹，合成一条回答，而不是二选一。

**镜头 7**
> 退款属于高风险写操作，系统不会直接执行：先给一个 dry-run 预览，生成审批单；管理员在面板上批准后才落地，重复批准是幂等的，不会重复建单。

**镜头 8**
> 知识库里没有的内容，系统明确拒答并转人工，不硬编；提示词越权、密钥探测这类请求在输入层就被拦下，直接转人工。

**镜头 9**
> 最后是评测。150 条任务 18 秒跑完，默认不调用外部模型，所以是零成本回归。当前基线：任务成功率 99.33%、路由准确率 100%、转人工召回 100%。

**镜头 10**
> 指标、评测报告、失败复盘和部署文档都在仓库里。当前边界是业务数据为本地模拟，下一阶段接真实订单与 CRM 系统。

## 录制小技巧

- **鼠标慢一点**：每步操作之间停 0.5–1 秒，剪辑时好切。
- **先录后配**：录屏时只操作不说话，后期按上面的稿子配音，字幕用剪映自动生成再改错别字。
- **画面加标注**：关键处用剪映的箭头/圆圈标出「FAQ 命中」「工具调用」「审批单」，面试官一眼能看懂。
- **别录失败操作**：提前演练两遍，把输入文字先打在记事本里，录制时直接粘贴，避免打错字浪费时间。
