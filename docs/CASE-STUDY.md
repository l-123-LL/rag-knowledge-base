# 一页项目案例

## 问题

原有系统是"企业客服 RAG"：能答知识库里的问题，但**做不了跨系统的业务任务**——查订单、查物流这类实时数据不在知识库里；工具或上游失败时只有一句"资料不足"；出了问题也无法还原执行过程。

## 方案

在**不重写**检索链路的前提下，增加一个可选的工具工作流：

`输入护栏 → 规则意图 → 订单/物流工具 → FAQ → 知识检索 → 质量判断 → 回答或转人工`

配套四件事：4 个带 schema 与超时重试的工具、逐次任务执行轨迹、100 条可复现评测集、输入护栏。

## 关键决策

| 决策 | 备选 | 为什么这么选 |
| --- | --- | --- |
| 工作流做成可选模式，默认 `rag` | 直接替换原链路 | 既有测试与演示不受影响，出问题一个参数回退 |
| 状态机自写 | LangGraph | 只做单跳任务，自写约 300 行可控；面试可讲清每步语义 |
| 业务数据用本地 mock | 接真实订单系统 | 无外部依赖即可演示；函数签名与真实 adapter 一致，替换只改一个文件 |
| 评测默认不调外部模型 | 每次全量真实生成 | 路由/工具指标不依赖生成质量，100 条 15 秒跑完、零 API 花费 |

## 指标（实测，非估算）

| 指标 | 数值 | 口径 |
| --- | --- | --- |
| 任务成功率 | 97.00% | 100 条评测，真实 BGE 嵌入，确定性生成 |
| 路由 / 工具选择准确率 | 98.00% | 同上 |
| 工具参数准确率 | 100.00% | 25 条带订单号的校验 |

| 转人工 Precision / Recall | 94.44% / 100% | 15 条应转人工的任务 |

| P50 / P95 延迟 | 1 ms / 94 ms | 不含真实模型生成 |
| 后端测试 | 98 passed | 含 33 个本阶段新增用例 |

## 失败与迭代（详见 FAILURE-CASES.md）

第一轮评测只有 72% 路由准确率：订单号存在但没匹配关键词时会掉到知识检索、物流关键词过宽导致误路由、订单查不到时被宽泛 FAQ 截走给出误导答案。修法是"有订单号默认查订单 + 收紧物流关键词 + 查不到不回退 FAQ"。

第二轮发现注入类任务全部未拦截，补了最小输入护栏。

第三轮发现阈值 0.42 会误伤 1/50 相关问题，采样出阈值-收益曲线后确认 0.42 仍是最佳操作点（挡 8/8 无关、保留 49/50 相关），把代价写进文档而不是藏起来。
